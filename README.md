# Шарики

Игра про шарики: они летают по белому полю, смешивают цвета при касании,
их можно всасывать мышкой в инвентарь и выплёвывать обратно, а попавшие
в красную зону — исчезают.

Проект собран в рамках урока **CLmB01 «Система контроля версий»**: логика
и интерфейс разрабатывались в отдельных ветках, слияние — через pull request,
релиз — через ветку `release/v1`.

## Как это работает

- Шарики двигаются с разной скоростью, отскакивают от стен и **не отталкиваются**
  друг от друга.
- При касании двух шариков их цвета смешиваются математически: новый цвет —
  усреднение RGB-компонент. Таблицы соответствий нет, поэтому работает для любого
  из 16,7 млн цветов. Белый цвет — «плохой» результат: он получается при
  многократном смешивании.
- **ЛКМ** (удерживать) — всасывать шарики в инвентарь.
- **ПКМ** — выплёвывать последний шарик из инвентаря в точку курсора.
- Красная пунктирная зона в правом нижнем углу — удаление: шарик, попавший в неё,
  исчезает.
- **R** — перезапуск, **Esc** — выход.
- Стартовое количество шариков задаётся константой `START_BALLS` в начале `gui.py`.

## Структура

```
git-balls/
├── gui.py            # точка входа: окно, отрисовка, управление мышью
├── logic.py          # игровая логика без интерфейса (движение, смешивание, инвентарь)
├── requirements.txt  # зависимости
├── Dockerfile        # запуск в контейнере с графическим окном (X11)
└── README.md
```

## Локальный запуск

Нужен Python 3.10+ (проверено на 3.13) и библиотека pygame.

```bash
python -m pip install -r requirements.txt
python gui.py
```

Если в системе несколько версий Python, запускайте тем интерпретатором, где
установлен pygame, например:

```bash
py -3.13 -m pip install -r requirements.txt
py -3.13 gui.py
```

## Запуск в Docker с графическим окном

Контейнеру нужно передать X11-дисплей хоста. Сборка:

```bash
docker build -t git-balls .
```

Linux (X11):

```bash
xhost +local:docker
docker run --rm -it \
  -e DISPLAY=$DISPLAY \
  -v /tmp/.X11-unix:/tmp/.X11-unix:rw \
  git-balls
```

macOS: нужен XQuartz, после его запуска — та же команда, что для Linux.

Windows: нужен внешний X-сервер. Проверено на Windows 11 + Docker Desktop 29.9.2
с VcXsrv:

```powershell
# 1. Установка X-сервера (один раз)
winget install -e --id marha.VcXsrv

# 2. Запуск X-сервера: TCP-порт 6000, без контроля доступа
& "C:\Program Files\VcXsrv\vcxsrv.exe" :0 -ac -listen tcp `
  -screen 0 1280x800x24 -multiwindow -clipboard

# 3. Запуск игры в контейнере
docker run --rm -e DISPLAY=host.docker.internal:0.0 git-balls
```

Проверить, что X-сервер слушает порт: `netstat -ano | Select-String ":6000"`
(должна быть строка `0.0.0.0:6000 ... LISTENING`).

⚠️ Флаг `-ac` отключает контроль доступа X11: подключиться к серверу может любой
в локальной сети. Для разовой проверки это допустимо, на постоянной основе лучше
так не держать — запускайте X-сервер на время игры и закрывайте после.

Если окно не появляется, проверьте, что X-сервер разрешает подключения,
Docker Desktop запущен и переменная `DISPLAY` указывает на него.

## Проверка логики без окна

Модуль `logic.py` не зависит от pygame, поэтому его можно проверить отдельно:

```python
from logic import BallWorld, mix_colors

print(mix_colors((255, 0, 0), (0, 0, 255)))  # (128, 0, 128)

world = BallWorld(ball_count=12)
for _ in range(600):
    world.update(1 / 60)
print(world.stats)
```

Для скриншота без открытия окна:

```bash
SDL_VIDEODRIVER=dummy python gui.py --frames 150 --shot shot.png
```
